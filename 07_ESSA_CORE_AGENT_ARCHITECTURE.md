# 07_ESSA_CORE_AGENT_ARCHITECTURE

## Статус документа

Этот документ описывает стратегическую архитектуру агентов внутри ESSA.

Он не описывает конкретную реализацию, backend, routing, интерфейсы, базу данных или runtime-логику.

Он определяет:

- что такое агент в ESSA;
- зачем агенты существуют;
- какие бывают типы агентов;
- как агенты взаимодействуют с человеком, проектами, пространствами и другими агентами;
- какие ограничения и принципы должны соблюдать агенты.

Документ следует после:

- `00_ESSA_CORE_PHILOSOPHY`;
- `01_ESSA_CORE_ECOSYSTEM`;
- `02_ESSA_CORE_LIFECYCLE`;
- `03_ESSA_CORE_PRINCIPLES`;
- `04_ESSA_CORE_ENTITIES`;
- `05_ESSA_CORE_RELATIONSHIPS`;
- `06_ESSA_CORE_BEHAVIORS`.

## Центральная идея

Агент в ESSA — это не просто AI-модель и не внешний сервис.

Агент — это функциональная сущность экосистемы, которая помогает человеку выполнять задачи, структурировать путь и реализовывать проекты.

Агенты не заменяют человека.

Они усиливают человека.

Агент существует не ради автономности самой по себе, а ради движения человека от намерения к идее, от идеи к проекту, от проекта к проявлению.

## Главный принцип

Агенты существуют для того, чтобы брать на себя повторяющиеся, технические, аналитические, организационные и производственные задачи.

Это освобождает человеку больше времени для:

- творчества;
- принятия решений;
- осознания направления;
- сотрудничества;
- создания нового;
- развития проекта;
- человеческого выбора и ответственности.

Агент не является центром ESSA.

Центр ESSA — человек.

## Что такое агент

Агент ESSA имеет:

- имя;
- роль;
- назначение;
- область ответственности;
- доступные знания;
- доступные инструменты;
- ограничения;
- правила взаимодействия;
- статус;
- связь с проектами и пространствами;
- возможность передавать результат другим агентам;
- trace или историю выполнения;
- правила approval gate там, где требуется подтверждение человека.

Агент должен быть понятен человеку: что он делает, зачем он подключён, какие результаты готовит и где требуется подтверждение.

## Типы агентов ESSA

### Navigator Agent

Помогает человеку понять намерение, идею и следующий шаг.

Navigator Agent работает на ранних этапах жизненного цикла ESSA: человек, осознание, намерение, идея, маршрут.

Он помогает не выбирать инструмент, а понять, что человек хочет создать.

### Production Agent

Помогает создавать контент, тексты, ролики, подкасты, музыку, визуалы и медиапакеты.

Production Agent работает с production-проектами, творческими workflows, медиапакетами, сценариями, asset-планами и result packages.

### Digital Identity Agent

Работает с цифровыми личностями, голосом, образом, стилем и паспортом личности.

Digital Identity Agent должен особенно уважать согласие, авторство, голос, образ и правила использования цифровой личности.

### Website Agent

Помогает создавать сайты, лендинги, интернет-магазины и онлайн-пространства.

Website Agent помогает пройти путь от намерения и задачи сайта к структуре, разделам, материалам, blueprint и project package.

### Property Agent

Помогает с недвижимостью, переездом, локациями, объектами и запросами.

Property Agent работает с человеческим контекстом, критериями, рисками, документами, локациями и маршрутом принятия решения.

### Business Agent

Помогает людям и компаниям создавать, развивать и структурировать бизнес.

Business Agent помогает оформлять идею бизнеса, процессы, команду, продукт, ценность, модель развития и операционный маршрут.

### Collaboration Agent

Помогает находить людей, команды, специалистов и партнёров.

Collaboration Agent соединяет проекты с людьми и людей с проектами, сохраняя смысл, роли, вклад и доверие.

### Education Agent

Помогает обучению, маршрутам развития, курсам и знаниям.

Education Agent поддерживает человека в развитии навыков, выборе маршрута, создании образовательных программ и накоплении знаний.

### Legal Agent

Помогает ориентироваться в правах, документах, процедурах и юридических вопросах.

Legal Agent не заменяет юриста.

Он помогает подготовиться, понять путь, собрать вопросы, документы и контекст для профессиональной проверки.

### Safety Agent

Помогает с защитой человека, семьи, детей, прав и кризисных ситуаций.

Safety Agent должен действовать бережно, ясно и с приоритетом безопасности человека.

### Economy Agent

Отслеживает ресурсы, usage, вклад, планы, кредиты и устойчивость системы.

Economy Agent помогает понимать экономику ценности, но не должен превращать ESSA в систему удержания или давления на человека.

### Resource Agent

Понимает стоимость действий, нагрузку, доступность инструментов и инфраструктурные ограничения.

Resource Agent помогает проектировать реалистичные workflows, не запуская платные или внешние действия без подтверждения.

### Publishing Agent

Помогает публиковать, планировать и распространять созданные материалы.

Publishing Agent должен ожидать подтверждения человека перед публикацией или отправкой материалов наружу.

### Translation Agent

Помогает переводить и адаптировать материалы под разные языки и культуры.

Translation Agent должен сохранять смысл, авторский стиль и культурный контекст.

### Voice Agent

Работает с голосом, озвучкой и voice identity.

Голос принадлежит цифровой личности и не используется без разрешения.

Voice Agent должен соблюдать voice usage policy и не применять голос одной личности к чужому проекту без явного согласия.

### Visual Agent

Помогает создавать визуальные образы, промпты, иллюстрации, дизайн и визуальные пакеты.

Visual Agent должен сохранять связь с авторством, visual identity, style guide и безопасностью изображения человека.

### Video Agent

Помогает планировать и собирать видео, клипы, мультфильмы, фильмы и avatar-video.

Video Agent работает с планом сцен, монтажной логикой, visual prompts, voice package, avatar brief и publishing package.

### Music Agent

Помогает создавать песни, музыку, звуковые образы и музыкальные проекты.

Music Agent должен уважать авторство, voice identity, стиль проекта и права на материалы.

## Жизненный цикл агента

1. Агент регистрируется в системе.
2. Агент получает назначение.
3. Агент подключается к пространству или проекту.
4. Агент получает задачу.
5. Агент выполняет подготовку или действие.
6. Агент возвращает результат.
7. Агент ожидает подтверждения человека, если это требуется.
8. Агент передаёт результат следующему агенту или в проект.
9. Агент сохраняет trace или историю выполнения.
10. Агент может обновляться по мере развития ESSA.

Жизненный цикл агента должен быть прозрачным: человек должен понимать, где агент находится в процессе и какой результат он подготовил.

## Взаимодействие агентов

Агенты могут:

- работать последовательно;
- работать параллельно;
- передавать результаты друг другу;
- собираться в pipeline;
- участвовать в workflow проекта;
- быть частью команды проекта;
- использовать общий project context;
- возвращать промежуточные результаты человеку.

Пример Content Multiplication pipeline:

```text
Source Analysis Agent

↓

Podcast Agent

↓

Shorts Agent

↓

Visual Agent

↓

Voice Agent

↓

Translation Agent

↓

Publishing Agent

↓

QA Agent
```

Pipeline агентов не должен автоматически запускать внешние, платные, публичные или чувствительные действия без approval gate.

## Human Approval Gate

Любое важное действие агента должно проходить через подтверждение человека.

Особенно:

- публикация;
- использование голоса;
- использование цифровой личности;
- отправка данных наружу;
- платные действия;
- юридические действия;
- действия с персональными данными;
- действия, влияющие на права, безопасность или репутацию человека;
- действия, которые невозможно легко отменить.

Approval gate защищает человека, авторство, цифровую личность, голос, данные и доверие к ESSA.

## Ограничения агентов

Агент не должен:

- присваивать авторство человека;
- использовать чужой голос без разрешения;
- использовать цифровую личность без согласия владельца;
- выполнять платные или внешние действия без подтверждения;
- публиковать материалы без разрешения;
- подменять профессиональную консультацию там, где требуется специалист;
- нарушать принципы ESSA;
- скрывать важные действия от человека;
- создавать зависимость, которая удерживает человека против его интересов;
- действовать вне своего назначения и области ответственности.

Ограничения агента являются частью безопасности экосистемы.

## Агент и человек

Агент всегда служит человеку и проекту.

Человек остаётся владельцем решения.

Агент предлагает, подготавливает, структурирует и помогает.

Агент должен усиливать способность человека понимать, выбирать и создавать, а не подменять его волю.

## Агент и проект

Проект может иметь одного или нескольких агентов.

Каждый агент выполняет свою роль.

Все результаты агента сохраняются как часть:

- истории проекта;
- assets;
- blueprint;
- workflow;
- execution plan;
- result package;
- project trace.

Агент должен оставлять результат в форме, которую может понять человек, команда или следующий агент.

## Агент и знания

Агент использует знания ESSA.

Знания могут быть:

- стратегическими документами;
- project context;
- user context;
- workspace context;
- domain knowledge;
- external verified knowledge, если оно разрешено;
- historical trace проекта;
- approved identity profile;
- approved assets.

Агент должен учитывать источник, актуальность, разрешения и контекст знания.

Знание не должно использоваться так, чтобы нарушать авторство, приватность или согласие.

## Агент и инструменты

Агент может использовать инструменты только если это разрешено архитектурой.

Инструменты могут быть:

- internal;
- local;
- external;
- paid;
- experimental.

Все внешние и платные действия должны иметь approval gate.

Инструмент не должен становиться главным результатом для человека.

Снаружи человек должен видеть ESSA, свой проект и понятный результат, а не набор разрозненных сторонних сервисов.

## Главный принцип

Агент не является центром ESSA.

Центр ESSA — человек.

Агент является помощником, усилителем и проводником между намерением человека и проявлением результата.

Если агент усиливает человека, сохраняет авторство, уважает цифровую личность, соблюдает approval gate и помогает проекту двигаться дальше, он соответствует ESSA.

Если агент подменяет человека, присваивает авторство, действует без согласия или разрушает доверие, его архитектура должна быть пересмотрена.

## Архитектурное значение

`07_ESSA_CORE_AGENT_ARCHITECTURE` должен использоваться при проектировании:

- новых агентов;
- agent pipelines;
- workflows;
- execution plans;
- tool access rules;
- approval gates;
- project handoff;
- multi-agent collaboration;
- resource and economy controls.

Любой агент ESSA должен быть описан через роль, назначение, ответственность, ограничения, знания, инструменты, approval gates и связь с человеком.

## Завершение

Этот документ фиксирует стратегическую архитектуру агентов ESSA.

Агенты делают экосистему сильнее только тогда, когда служат человеку, проекту и принципам ESSA.

Все будущие агенты должны проектироваться как помощники человека, а не как замена человека.
